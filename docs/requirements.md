# md-live-preview 要件定義

## 1. 概要

指定ディレクトリ内の Markdown ファイルを監視し、追加・変更を即座に HTML 変換してブラウザにライブ表示するローカル CLI ツール。
あわせて、外部参照を持たない単一ファイル完結の HTML を書き出す機能を持つ。

- コマンド名: `mdlive`
- 実装: Node.js 22.18+ / TypeScript (strict) / ESM / pnpm

## 2. CLI

### 2.1 コマンド

| コマンド | 説明 |
|---|---|
| `mdlive [dir]` / `mdlive serve [dir]` | Web サーバを起動し、ブラウザを開いてライブプレビューする（デフォルト） |
| `mdlive build [dir] --out <dir>` | 静的 HTML を一括出力して終了する |

`dir` 省略時はカレントディレクトリ。

### 2.2 オプション

| オプション | 対象 | 説明 |
|---|---|---|
| `--port <n>` | serve | ポート番号（デフォルト 3000、使用中なら番号を 1 ずつ増やして最大 20 個まで空きポートを探す） |
| `--host <addr>` | serve | バインドアドレス（デフォルト `127.0.0.1`） |
| `--no-open` | serve | ブラウザを自動起動しない |
| `--out <dir>` | serve / build | HTML 出力先。serve では指定時のみ変更のたびに出力する。build では必須 |
| `--css <path>` | serve / build | カスタム CSS。GitHub スタイルの後に適用（上書き方式） |
| `--theme <mode>` | serve / build | 配色。`auto`（OS のライト／ダーク設定に追従、デフォルト）/ `light` / `dark` |
| `--no-default-css` | serve / build | デフォルトスタイル（GitHub スタイルとレイアウト）を無効にする |
| `--front-matter <mode>` | serve / build | フロントマターの表示。`table`（表で表示、デフォルト）/ `hide`（非表示） |
| `--strict` | build | 参照画像の欠落などの警告をエラー扱いにして失敗させる |

### 2.3 終了

- Ctrl+C（SIGINT）または SIGTERM で watcher・サーバ・SSE 接続をクリーンアップして終了する。
  2 回目のシグナルを受けた場合、または 5 秒以内に終わらない場合は強制終了する。
- ブラウザの起動に失敗してもサーバは止めず、URL を案内する。

## 3. 機能要件

### 3.1 ファイル監視

- サブディレクトリを再帰的に監視する。
- 対象拡張子: `.md`, `.markdown`、および画像（png / jpg / gif / webp / avif / svg）
- 検知イベント: 追加・変更・削除・リネーム
- エディタの連続保存や一時ファイルへの多重反応を防ぐため、50〜100ms 程度の debounce を行う。
- `node_modules`, `.git` および出力先ディレクトリ（`--out`）は監視対象から除外する。
- カスタム CSS ファイルも監視し、変更を即反映する。
- 画像の追加・変更・削除時は、その画像を表示している `<img>` だけをキャッシュ回避付きで再読み込みする（イベント `asset`）。
  `--out` 指定時は、その画像を埋め込んでいるページ（参照先が存在せず埋め込めなかったページを含む）を書き出し直す。

### 3.2 Markdown 変換

- GitHub Flavored Markdown: テーブル、タスクリスト、取り消し線、自動リンク、脚注
- コードブロックのシンタックスハイライト（Shiki、`github-light` / `github-dark` のデュアルテーマ）
- 見出しアンカー（GitHub 互換の slug）
- 数式: `$...$` / `$$...$$` を KaTeX でサーバサイドレンダリング
- Mermaid: ` ```mermaid ` ブロックをクライアントサイドで `mermaid.js` により描画し、ライト／ダークに追従する
- 生 HTML: 許可した上で GitHub 準拠のスキーマでサニタイズする
- フロントマター: ファイル先頭の `---` 〜 `---` で囲んだ YAML を本文と区別して扱う（TOML の `+++` は対象外）
  - `table` では GitHub と同様に本文の前に表として表示する。1 行目にキー、2 行目に値を並べ、配列・オブジェクトの値はセル内に表を入れ子にする
  - `hide` では表示しない
  - YAML の解析に失敗した場合は警告を出し、`table` では元の YAML をコードブロックとして表示する（`hide` では警告のみ）
  - 値はすべてテキストとして出力し、HTML として解釈しない
- コンテナディレクティブ: `:::name` 〜 `:::` で囲んだ範囲を `<div class="name">` に変換する
  - 中身は通常の Markdown として変換する。名前は必須で、名前のない `:::` はディレクティブにならず通常のテキストとして表示する
  - ネストは外側のコロンを内側より多くして書く（例: `::::outer` の中に `:::inner`）
  - ラベル `:::name[ラベル]` は div 先頭の段落として出力する。属性 `{...}` は無視する
  - 行内の `:name` と行単位の `::name` はディレクティブとして扱わず、元の文字列のまま表示する
  - クラス名は英字で始まる英数字・`-`・`_` のみ許可する（サニタイズで div の `class` をこの形式に限り許可する）
- 相対リンク・画像パスを正しく解決する。`.md` へのリンクは serve ではプレビューページへ、出力 HTML では `.html` へ書き換える。

### 3.3 ライブプレビュー（serve）

#### 画面

| パス | 内容 |
|---|---|
| `/` | ファイル一覧（ツリー表示）。ファイルの追加・削除を即反映する |
| `/<path>.md` | 個別プレビュー |
| `/__mdlive/*` | 内部用（SSE、HTML 断片、アセット） |

#### ライブ更新

- サーバからブラウザへの通知は SSE で行う。
- 変更されたファイルのみを再変換し、該当パスを表示中のタブだけを更新する。
- 更新はページ全体のリロードではなく `<article>` 本文の差し替えで行い、スクロール位置を保持する。差し替え後に Mermaid を再描画する。
- 新規ファイル追加時は一覧への反映のみとし、自動で遷移はしない。

| イベント | ブラウザの動作 |
|---|---|
| `update` | 本文を差し替える |
| `tree` | ファイル一覧を更新する |
| `css` | カスタム CSS をキャッシュバスティング付きで再読み込みする |
| `asset` | 変更された画像を表示している `<img>` をキャッシュバスティング付きで再読み込みする |
| `error` | 変換エラーをページ上部にバナー表示する |

### 3.4 スタイル

- デフォルトは `github-markdown-css` を使い、OS のライト／ダーク設定（`prefers-color-scheme`）に追従する。
- `--theme light` / `--theme dark` 指定時は OS の設定に関わらず配色を固定する。
  GitHub スタイル（`github-markdown-light.css` / `github-markdown-dark.css` を使用）、背景色、コードハイライト、Mermaid の配色、`color-scheme` のすべてを指定に揃える。
- `--css` 指定時はデフォルトスタイルの後に読み込み、上書きする（置換モードは持たない）。
- `--no-default-css` 指定時は、見た目のためのデフォルトスタイル（GitHub スタイル、本文の幅・余白、背景色、コードブロックの背景色）を読み込まない。
  - 表示に必要な最小限のスタイルは残す: KaTeX の CSS、脚注見出しなどスクリーンリーダー向け要素を隠す指定、コードハイライトのライト／ダーク切り替えと `color-scheme`（`--theme` に従う）、serve のエラーバナー
  - `<article class="markdown-body">` はそのまま出力し、カスタム CSS から指定できるようにする

### 3.5 HTML 出力（build / serve --out）

出力 HTML は **外部ファイルを一切参照しない単一ファイル完結形式** とし、1 ファイル単独で配布できること。

| 対象 | 埋め込み方法 |
|---|---|
| GitHub スタイル / カスタム CSS | `<style>` にインライン |
| Shiki ハイライト | インライン style（変換結果そのまま） |
| ローカル画像（png / jpg / gif / webp / svg） | Base64 data URI |
| KaTeX | CSS と woff2 フォントを data URI でインライン。数式を含むページのみ |
| Mermaid | `mermaid.min.js` を `<script>` にインライン。Mermaid を含むページのみ |
| 外部 URL 画像（`http(s)://`） | そのまま残す |

- ディレクトリ構造を保って `<out>/<path>.html` に出力し、ファイル一覧の `index.html` も生成する。
  ただしルートに `index.md` 等があり `index.html` が生成される場合は、一覧は生成しない。
- 出力先はルート配下でもよい（走査から除外する）が、ルート自身やその親ディレクトリは指定できない。
- `a.md` と `a.markdown` のように同じ出力パスになるファイルがある場合はエラーとする。
- ルートディレクトリ外の画像は埋め込まず、警告を出す。
- 1 ファイルの変換・書き出しに失敗しても残りのファイルは出力し、終了コードを 1 にする。`--strict` 時の警告も同様。
- `.md` へのリンクは `.html` へ書き換える。単一ファイルで配布した場合のページ間リンク切れは仕様として許容する。
- 参照画像が存在しない場合は警告を出し、元のパスを残す（`--strict` 時はエラー）。
- 1 ページが 10MB を超える場合は警告を出す。
- serve で `--out` 指定時は、変更のたびに該当 HTML を再出力し、元の Markdown 削除時は対応する HTML も削除する。

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| 応答性 | ファイル保存からブラウザ表示更新まで 200ms 以内を目安とする |
| 対応 OS | macOS / Linux / Windows |
| セキュリティ | デフォルトは localhost のみで待ち受ける。ルートディレクトリ外へのパストラバーサル（シンボリックリンク経由を含む）とドットで始まるパスの配信を禁止する。DNS リバインディング対策として Host ヘッダを検証する。生 HTML はサニタイズする |
| エラー処理 | エラーは握りつぶさず、対象ファイルと処理段階が分かるメッセージを出力する。1 ファイルの変換失敗でサーバを停止しない |

## 5. スコープ外（初版）

- PDF 出力
- ブラウザ上での編集
- 外部 URL 画像の取得・埋め込み（将来 `--inline-remote` として検討）
- カスタム CSS の置換モード
